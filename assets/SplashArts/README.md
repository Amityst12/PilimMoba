# 🎨 Pilim MOBA: מדריך והנחיות לעיצוב Splash Art (Loading Screen Art)

ברוכים הבאים לתיקיית ה-**Splash Arts** של **Pilim MOBA**.  
תיקייה זו מיועדת לאחסן את איורי ה-Splash Art המלאים של הדמויות, אשר יוצגו במסך הטעינה (Loading Screen), במסך בחירת הדמויות (Lobby / Champion Select) ובמסכי הניצחון וההפסד.

---

> [!NOTE]
> **מה ההבדל בין סמל הדמות (Icon) לבין Splash Art?**
> - **Icon (`assets/icons/champions/`):** סמל וקטורי מרובע וקטן (80x80 עד 256x256) המיועד למיני-מפה, ממשק ה-HUD בתוך המשחק, לוח התוצאות (TAB) וחנות הפריטים.
> - **Splash Art (כאן):** איור קונספטואלי/אמנותי פנורמי מרהיב באיכות גבוהה (כמו ב-League of Legends או Dota 2), המציג את הדמות בפעולה, עם תאורה עשירה, רקע אטמוספרי ועומק עלילתי.

---

## 📐 1. מימדים ויחסי תצוגה (Dimensions & Aspect Ratios)

במשחק מתוכננים שני פורמטים עיקריים לשימוש:

### א. תמונת רוחב פנורמית – Landscape 16:9 (מומלץ כ-Master Illustration)
איור שלם ורחב המציג את הדמות בתוך הסביבה והעולם שלה.
- **רזולוציה מומלצת:** `1920 × 1080` פיקסלים (Full HD) או `2560 × 1440` (2K QHD).
- **יחס גובה-רוחב (Aspect Ratio):** **16:9** (תואם למסכי מחשב סטנדרטיים ולמסך המלא של המשחק).
- **שימושים עיקריים:**
  - רקע מסך הטעינה הראשי.
  - באנר פנורמי בלובי / מסך בחירת דמות (Champion Pick Banner).
  - רקע מסך סיום משחק (Victory / Defeat Screen).

### ב. קלף טעינה אנכי – Vertical Loading Card (חיתוך בסגנון League of Legends)
חיתוך אנכי ממוקד המציג את פלג הגוף העליון, פני הדמות וכלי הנשק שלה בתוך "כרטיס שחקן" (VS Loading Screen).
- **רזולוציה מומלצת:** `600 × 1000` פיקסלים (או `1200 × 2000` פיקסלים לאיכות Ultra-HD).
- **יחס גובה-רוחב (Aspect Ratio):** **3:5** (או יחס `1:1.67`).
- **שימושים עיקריים:**
  - עמודות קלפי שחקנים במסך הטעינה (שחקני קבוצה כחולה מול שחקני קבוצה אדומה זה לצד זה).

## 💾 2. פורמט קובץ, איכות ודחיסה (File Formats & Compression)

| פורמט | רמת מומלצות | יתרונות והנחיות |
|---|---|---|
| **WebP** | ⭐⭐⭐ **הכי מומלץ** | איכות מושלמת, משקל קובץ קל פי 2-3 מ-PNG, תמיכה מלאה וטעינה סופר-מהירה ב-Godot 4. מומלץ לשמור ב-Lossy 92-95% או Lossless. |
| **PNG** | ⭐⭐ **מומלץ מאוד** | פורמט Lossless נטול פשרות (24-bit RGB או 32-bit RGBA). אידיאלי לקובץ המאסטר המקורי. |
| **JPEG** | ⭐ **חלופה** | קובץ קל משקל. מומלץ לשמור באיכות מקסימלית (Quality 95% ומעלה) ללא ארטיפקטים. |

- **מרחב צבעים (Color Profile):** **sRGB** בלבד (RGB של 8 סיביות לערוץ). **אין להשתמש ב-CMYK!**
- **משקל קובץ יעד (Target File Size):** **בין 800KB ל-2.5MB** לתמונה מלאה.

## 🔍 4. קומפוזיציה ואזורים בטוחים (Composition & Safe Zones)

בעת יצירת או חיתוך האיור, יש לקחת בחשבון את שכבות הממשק (UI Overlays) של מסך הטעינה:

```text
┌─────────────────────────────────────────────────────────────┐
│                       [אזור ראש / מבט]                      │
│                  - Focal Point (פני הדמות)                  │
│                                                             │
│                    [אזור גוף ונשק מרכזי]                    │
│                                                             │
│ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │ <── Safe Zone:
│ ░░ שמות שחקנים, סמלי כשפים, פס טעינה %, מסגרת דרגה (15-20%) ░░ │     אין לשים פנים
└─────────────────────────────────────────────────────────────┘
```

1. **מוקד העניין (Focal Point):**
   - פני הדמות, העיניים וההבעה צריכים להיות ממוקמים ב-**שליש העליון של הפריים** (חוק השלישים).
2. **אזור ה-UI התחתון (Bottom 15-20%):**
   - בחלק התחתון של המסך מוצגים שמות השחקנים, אחוזי הטעינה, סמלי ה-Summoner Spells ועיטורי הרמה. לכן יש להשאיר שם רקע או את פלג הגוף התחתון, ולא להסתיר פריטי מפתח.
3. **שוליים מוגנים (5% Margin):**
   - מומלץ להשאיר שוליים של 5% בכל צד כדי למנוע קטיעת אלמנטים חשובים בעת מתיחה או התאמה ליחסי מסך שונים (למשל 16:10 או מסכים רחבים).

## ⚙️ 6. איך המנוע משתמש בתמונות (Godot Integration)

1. **זיהוי אוטומטי במנוע:**
   ברגע שתניח קובץ בשם `<champion_id>_splash.png` (או `_card.png`) בתוך תיקייה זו, המשחק יטען אותו אוטומטית למסך הטעינה ולמסך בחירת הדמויות דרך `ChampionData.get_splash_art()`.
2. **הגדרות ייבוא מומלצות ב-Godot 4:**
   - **Compress Mode:** `VRAM Compressed` (Lossless/High Quality) עבור קבצי טקסטורות ממשק.
   - **Mipmaps:** מומלץ להשאיר כבוי (`false`) עבור UI כדי לשמור על חדות מרבית של הטקסטורה.
